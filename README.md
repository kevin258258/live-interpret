# Live Interpret

面向 VTuber 和海外直播的实时中文字幕工具。当前先把 Linux 浏览器体验做好，iPad / iPhone / macOS 保留为后续方向。

Linux 首版已经包含本机工作台、Chrome / Chromium 扩展、音频分段上传、英日识别及中文翻译链路。自带的文字示例不采集音频、不调用 API。真实同传需要填写自己的 OpenAI 兼容服务。

## 运行 Linux 首版

需要 Node.js 22+、Chrome / Chromium 116+。运行服务无需 npm install，没有运行时第三方依赖。

```sh
git clone https://github.com/kevin258258/live-interpret.git
cd live-interpret
npm start
```

1. 打开终端显示的完整工作台链接（包含 `#` 后的连接码）。
2. 在「配置 API」中分别填写识别和翻译的基础地址、模型名及密钥。基础地址通常形如 `https://your-provider.example/v1`，不要填写网页聊天地址。
3. 打开 `chrome://extensions`，开启开发者模式，加载本项目的 `extension` 文件夹。
4. 点击扩展，粘贴工作台完整连接地址并配对。服务每次启动都会更换连接码；重启服务后重新配对。
5. 在 YouTube / Twitch 播放页面点击扩展 →「开始同传」。安装前已打开的直播标签页需要刷新一次。

工作台的「连接浏览器扩展」提供安装路径和一键复制连接地址。`Alt + Shift + S` 隐藏 / 显示字幕；扩展和工作台均可停止会话。

字幕直接附着在浏览器播放器区域，全屏时移动到全屏容器。它不依赖 Linux 的跨窗口透明浮层，因此无需先解决 Wayland / X11 的置顶窗口差异。当前实现不覆盖 Firefox、原生播放器或系统其他 App 的音频。

## API 要求

| 用途     | 请求                                                                                                                                               | 预期返回                            |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| 语音识别 | `POST {识别基础地址}/audio/transcriptions`，multipart `file`（16kHz 单声道 WAV）、`model`、`response_format=json`，可选 `language` 和术语 `prompt` | `{ "text": "原文" }`                |
| 中文翻译 | `POST {翻译基础地址}/chat/completions`，`model`、`messages`、`stream=false`                                                                        | `choices[0].message.content` 为译文 |

两个服务可以分别配置；密钥可留空以接入不鉴权的本地兼容服务。留空的密钥输入不会覆盖已保存密钥；需要删除时勾选移除。模型名由服务商确定，不预设某个可用模型。

接口格式依据 [官方 OpenAI 转写文档](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create) 和 [Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。任意“聊天 API”不一定支持音频转写，需确认服务商同时提供所需路径。测试翻译按钮会调用已保存的服务并产生对应服务商用量。

## 已实现的观看体验

- 仅在点击开始后采集选定标签页的数字音频，独立输出原声；不使用麦克风回录。
- 日语 / 英语 / 自动识别，以及三种断句模式。
- 中文字幕、可选原文、字号 / 位置 / 背景深浅实时调节。
- 术语表同时用于识别提示与翻译；翻译带最近两个片段的上下文。
- 最近字幕回看和主动导出双语文本，导出时间是处理时间而非视频时间码。
- 有限队列跳过积压片段，显示处理耗时；停止、切源、音频断开时取消旧会话，防止旧字幕串台。
- 连续接口错误时停止采集；服务连接中断时停止浏览器采集。

当前按音频能量分段后调用文件转写接口，并非模型原生实时流。字幕延迟包含等待断句、排队、识别和翻译；界面“片段处理耗时”只测量服务器接收片段后的排队与处理，不代表完整端到端延迟。能量检测不能可靠区分人声与背景音乐，歌回 / 游戏音效密集场景仍需实测调优。

## 数据与配置

- 服务仅监听 `127.0.0.1`，默认端口 `43821`，可通过 `PORT` 修改。
- API 密钥只保存在 `.local/config.json`（文件权限 `0600`）；扩展只保存本机配对码，直播网页拿不到 API 密钥。
- 原始音频只在内存短暂处理，不写入磁盘。音频会发送给识别服务，识别文本、最近上下文和术语会发送给翻译服务；其保留政策由所选服务商决定。
- 字幕仅在内存保留最近记录；关闭服务不持久保存。主动导出的文件由用户保留。
- `.local/` 与测试截图 `artifacts/` 已加入忽略列表，不要分享工作台完整连接链接。

可用 `LIVE_INTERPRET_DATA_DIR` 指定配置目录。不需要读取或复用其他项目的密钥。

## 验证与当前边界

```sh
npm run check
npm test
```

另有 `npm run test:browser` 和 `npm run test:extension`：需要自行安装 Playwright 或通过 `PLAYWRIGHT_MODULE` 指定其入口，`CHROMIUM_PATH` 可指定 Chromium 可执行文件。前者测试工作台和播放器布局，后者在新 Chromium 中测试真实扩展 tabCapture（合成音源，模型为本机模拟）。均不调用付费接口。截图输出到 `artifacts/`。

验证记录见 [Linux 首版实现与验证](docs/linux-first.md)。真实服务的质量、长时间直播、蓝牙输出切换仍需在用户桌面会话中实测；不以模拟 API 测试宣称已经验证真实识别准确率或直播延迟。

## 长期使用需求

- 核心场景：躺在床上，用 iPad 看 VTuber 直播，同时阅读中文字幕。
- 移动端目标设备：最新 iPad Air，适配最新正式版 iPadOS。
- 首批观看平台：YouTube、Twitch；移动端以官方 App 为主，当前阶段先实现 Linux 浏览器。
- 覆盖设备：iPad、iPhone、macOS、Linux 桌面。
- 使用习惯：iPad / iPhone 以官方 App 为主，桌面以浏览器为主；两种入口都需要适配。
- 输入语言：英语、日语。首版输出按简体中文设计。
- 输出：实时字幕，保留主播原声；当前不需要中文配音。

YouTube / Twitch 的确认适用于首批兼容性验证，不代表其所有播放模式已经测试通过。

## 体验目标与待确认项

以下是根据观看场景提出的设计目标，还不是已经交付的能力：

- iPad 独立启动、观看和停止字幕；运行时无需旁边有一台开着的电脑。
- 日常操作尽量少，横屏、大字号、低亮度下仍可阅读。
- 字幕尽量少遮挡人物和直播已有文字，提供位置、字号、背景调节。
- 区分正在生成和已经确认的字幕，避免整段反复跳动。
- 支持主播名、角色名、游戏名的个人术语表；不认识的梗允许保留原词。
- 网络中断、音频中断、切换直播时，明确显示状态并清理过期字幕。
- 默认不持久保存音视频和完整观看历史；若使用远端服务，明确处理位置和保留策略。

字幕叠加在官方 App 全屏画面上是优先验证的理想效果。分屏、窗口布局、画中画组合是候选方案，其可接受程度尚未由用户确认。在线服务、家中服务器、完全本地推理的选择也尚未确定。

## 后续移动端方向

采集声音、识别翻译、展示字幕分开验证。各端可共享字幕会话与术语数据，但分别使用经过验证的采集和展示方式。

本次调研以 2026-10-15 为时间点；Apple 已于 2026-09-14 公布 iPadOS 27 正式可用，因此先围绕当前正式系统做验证，具体安装版本以真机记录为准。[Apple 发布公告](https://www.apple.com/newsroom/2026/09/major-updates-for-apples-software-platforms-are-now-available/)

Linux 浏览器链路稳定后，再验证 iPad 官方 App 音频采集与字幕布局。移动端单独评估 ScreenCaptureKit；不能将浏览器扩展覆盖网页的能力视为能够覆盖其他原生 App。

原始音频可以来自系统的屏幕共享机制，但翻译链路仅需要声音；若平台必须产生视频帧，优先在设备上丢弃，不上传、不落盘。

## 后续 iPad 真机通过标准

这一阶段验证平台可行性，不把能打开字幕界面等同于已经完成同传：

- 在用户目标 iPad 上，分别记录 YouTube / Twitch 的 App 版本、系统版本、地区及相关订阅条件。
- 不使用麦克风收录扬声器声音，佩戴蓝牙耳机时也能获取目标直播的声音。
- 连续观看时，主播原声、实时音频采集、字幕显示同时工作。
- 测试官方 App 全屏及候选布局；明确记录哪一种实际通过，不能以分屏通过声称全屏叠字通过。
- 暂停、恢复、切换直播、转屏、音频输出切换、断网时不会继续显示过期字幕。
- 一次连续观看至少 30 分钟，记录采集中断、温度和电量变化；这些时长是拟定测试条件，尚无实测结果。
- 无法捕获的内容、权限或播放模式明确报出原因。

真机闭环成立后，再确定首字延迟、稳定译文延迟和质量指标；当前没有延迟或翻译质量实测数据。
